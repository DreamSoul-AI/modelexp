# Codex 模型日报完整工作流程

## 工作边界与调度

Codex 负责发现、核查、制备日报和调研正文。生产与发布分两步。模型、Benchmark、量化和渠道可以分别交给子代理研究，主任务负责合并、元数据核对和发布。业务日期使用 `Asia/Shanghai`。预定在现有北京时间 12:00 同步前完成可用产物，来源晚到或部分失败按产物独立接续。模型调用前检查账户额度，任一窗口已用达到 90%、额度无法确认或到北京时间 18:00 时暂停并保留进度。

## 发现、核查与成文

1. 确定本轮业务日期、扫描起点和截止时间，记录实际访问的渠道、检索条件、失败和未覆盖项。以已确认的渠道清单为入口，优先检索 Hugging Face、GitHub 和 arXiv。区分新发布、新修订和以前漏收的补充发现。
2. 用现有表格、已交付 CSV 和 `md/` 比较来源 URL、revision 和具体变体。模型以主来源、修订和具体模型配置定位。Benchmark 记录版本和协议。量化或衍生制品逐一核对基座、产物文件和精确修订。未知身份或冲突进入待核实清单。
3. 读取固定版本的模型卡、配置、README、文件列表、许可或论文。逐项记录真实链接、revision、阅读范围、发现时间和核查状态。明确区分发布方声明、第三方报告和团队实测。
4. 模型保留模态、任务、规模、许可、开放范围、运行支持和限制。架构、运行框架及输入输出可在正文写明，按现有 13 列产出模型 CSV。Benchmark 记录数据规模、指标、协议、用法和端侧相关性。制品记录基座和训练关系、发布身份、格式、精度、文件和测量条件，速度、显存和效果只用本制品的可核验证据。
5. 模型和 Benchmark 分别按对象及 revision 成文。正文含基本信息、适用范围、能力与实现、评测口径、制品及运行、限制与待核实项、来源与阅读范围。事实就近引用 `[S1]` 等编号。量化明细进量化 CSV，相关材料归入对应模型正文。对已有正文保留人工内容并记录拟议差异。

## 飞书交付

日报根目录沿用现有 `model/benchmark日报`。本工作流程文档另放在用户指定的工作资料目录。

| 产物 | 相对日报根目录的路径 | 内容与格式 |
|---|---|---|
| 模型日报 | `model/model_daily_{date}.csv` | 13 个现有字段 |
| Benchmark 日报 | `benchmark/benchmark_daily_{date}.csv` | 14 个现有字段 |
| 渠道清单 | `channel/channels_{date}.csv` | 12 个现有字段，渠道 ID 延续原清单 |
| 来源清单 | `channel/source_links_{date}.csv` | 7 个现有字段，用于追踪来源和核查状态 |
| 量化与衍生制品日报 | `quant/Quant Trail_daily_{date}.csv` | 29 个现有字段，以制品文件与修订为粒度 |
| 调研正文 | `md/{date}/` | 原生 Markdown，沿用 `models_组织__仓库_短revision.md` 和 `benchmarks_组织__仓库_短revision.md` |

CSV 使用 UTF-8 BOM、原列顺序和标准逗号分隔格式。多行及逗号由 CSV 引号封装。数值列只填明确的单个值，未知填空，额外测试参数进说明列。分开记录确无新增、采集失败和扫描覆盖不足。现有同步需要明确的生产确认才能接收只有表头的 CSV。零新增日先保留本地结果和完成原因，待该交接路径通过验收后再发布空表。

## 校验、发布与下游任务

1. 将文件先生成到私有暂存目录，记录业务日期、扫描范围、候选对象、来源、未覆盖项、产物计数和 SHA-256。检查 CSV 表头和列数、可写类型、关键身份、重复记录和实体对应关系。分别验收 CSV 与正文覆盖范围。
2. 发布时按目录和文件名核对飞书现状。已存在且内容相同视为成功。已有不同内容需要对账，提交结果不明先回读。逐件核对远端位置、唯一文件名、内容散列和行数。
3. 四类正式 CSV 由现有程序逐表同步，校验服务独立只读检查。模型表完成后，评分服务核查文字输出语言模型的代码、Agent、数学成绩，沿用冻结版本和证据规则。服务器更新 `md/README.md` 的资料索引和统计。`md/existing/`、`md/backfill/` 作为历史资料保留。
4. 先用已交付业务日做旁路重跑，再用新日期验证稳定性与下游读取。比较候选覆盖、证据质量、已有身份匹配和重试结果。正式切换时由 Codex 独占日报发布，并记录首轮实际交付、飞书回读与同步结果。

## 运行入口

Codex 研究任务先阅读本文件、现有正文模板和 `skills/model-research/assets/daily-delivery-columns.json`，再生成暂存目录。目录结构与飞书日报一致。`coverage.json` 记录 `business_date`、各渠道的时间窗和覆盖、已核查来源、未覆盖原因、各产物状态及审阅结果。旁路状态使用 `shadow`。主任务完成全轮覆盖审阅后，正式包使用 `accepted`。

```bash
python3 skills/model-research/scripts/daily_delivery.py check \
  --config <现有CSV配置> --date <业务日> --bundle <暂存目录>
```

复用相同参数运行 `publish` 即可交付已接受的日报包。发布器先核对 飞书 目录、文件名和内容，再用官方飞书 CLI 上传 CSV、创建原生 Markdown，并持久保存操作意图和回读回执。发生中断后使用同一批文件接续。校验结果写入暂存目录的 `delivery-check.json`。

首轮迁移先运行旁路验证。现有生产发布和定时同步继续运行，便于用同一套飞书字段和下游读取规则验收 Codex 产物。正式切换需完成日程、来源覆盖和首次全链路验收。
