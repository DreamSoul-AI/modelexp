# 模型资料与评分维护架构

## 每日流程

北京时间12:00，CSV 同步与只读校验分别启动。同步按业务日读取 Grokbot 指定子目录，逐表保存原件与哈希，至少两次相同内容、间隔60秒后视为暂时稳定；生产方完成 manifest 可直接确认。稳定观察按业务日和表隔离，一表晚到或变化不重置其他表。每表分别计划、写回和回读；缺失、损坏或访问失败只影响本表，其他就绪表继续，整体报告保留 partial。同步只处理本轮输入，不删除历史缺行记录。

CSV 按已核实的 field_id 和类型转换，可确定的格式问题自动归一；多选加号仅在所有分项均为已有选项时拆分，完整选项和明确别名优先。形成计划，写前检查当前值、来源和基线，批量写入后回读。只有已验证值推进基线。校验读取四张表与当前 CSV，逐字段比较，区分人工保护、初始差异和冲突，输出具体行/字段问题；校验不修表、不调用模型，也不核实资料本身的真实性。

评分任务只等待同业务日模型表稳定且同步完成，读取独立完成回执，不等待其他三表或整个 CSV worker 结束。先扫描模型主表与已有能力视图的字段，排除无文字输出的模型；有文字输出的多模态模型仍须核实其生成式语言能力，ASR/OCR、向量、打分模型不自动纳入。读取实际官方模型卡或原始入口，来源变化时让 Codex 提取代码、Agent、数学的版本与配置明确成绩。相同来源和记录跳过模型调用；专项与基座保持单列。

结果必须引用实际读取的本实体原文，原始分必须有 Benchmark 版本与测试配置。字段白名单只包含三能力，新 Benchmark 保存映射候选，不自动创建列或扩充能力。写回沿用计划、人工修改保护和回读；没有证据不补0，不将别的变体或底层模型成绩移植进来。

## 冻结评分

v0.3 按独立 Benchmark 保留固定模型配置样本。标化为 `100 × (参考样本中小于 x 的数量 + 同分数量 / 2) / N`，相同值同分；新值按固定分布求值，低于/高于所有参考值为0/100。参考样本不随日常新增或修订而改变。已有原始分保留，统一重算标化分，公式能力分随之更新。

代码保留50% LCB v6、40% SWE Verified、10% HumanEval+；Agent 保留30% BFCL v4、40% Terminal 2.1、30% τ²；数学保留50% AIME、30% HMMT Feb、20% MATH-500，年份分组。只对存在子项的权重归一；覆盖不足70%或有效子项少于2不出能力分。公开报告的框架、思考预算、工具与协议差异仍须阅读依据，标化不把异构成绩变成统一实测榜单。

## Grokbot 目录

`model/`、`benchmark/`、`channel/` 为日常 CSV，`quant/` 文件名为 `Quant Trail_daily_{date}.csv`；量化文件缺失可独立跳过，不把旧日期当今天。量化 CSV 的27列按实际类型映射；`原模型记录` 是名称而线上为关联记录，`效果证据` 是长句而线上为枚举，暂保留原件，不猜关联或强行归类。`md/existing`、`md/backfill` 不触发生成、搬动或删除；source_links/backfill 不进入输入。

## 运行与恢复

三个 systemd 服务独立持久化，不使用旧 research/jobs 队列。评分按记录回执推进，每次新调用前查询官方额度；任一窗口使用达到90%、额度未知或北京时间18:00时暂停。默认无每日调用次数上限，保留累计计数；可显式另配正整数上限。临近18:00缩短模型超时并保留清理时间，失败产物保留并退避；已提交的表格修改仍需回读核验。恢复后根据当前状态继续，不回放已验证写入。无自动通知和每日变更摘要。

评分版本、公式与参考样本数见[冻结评分规则](../../skills/model-research/references/scoring.md)。
