# Codex 模型日报完整工作流程

## 工作边界与调度

Codex 负责发现、核查、制备日报和调研正文。北京时间 12:00 开始，systemd 每 15 分钟检查是否需要接续，业务日期使用 `Asia/Shanghai`。生产、发布和同步分开，CSV 同步等当天发布回读后的交接文件。每次模型调用前检查账户额度，任一窗口已用达到 90%、额度无法确认或到北京时间 18:00 时暂停并保留进度。

## 发现、核查与成文

1. 正式采集读取 Hugging Face 模型和数据集、GitHub Benchmark 仓库搜索、arXiv 相关摘要和链接。记录三天重叠窗口、候选上限、实际访问的来源、读取失败和未检查的候选。渠道 CSV 沿用最近正式清单中的渠道 ID；清单中的其他渠道是参考入口。
2. 发布前对照实时表格、已交付 CSV 和 `md/`，按规范化名称、仓库或论文身份去重。同一模型或 Benchmark 的链接变体及修订变更不重复入日报。量化按仓库和文件名匹配，复传相同文件不会重复入日报。新条目仍保存精确修订、版本和证据。无法区分已有对象与新对象的条目跳过。
3. 读取固定版本的模型卡、配置、README、文件列表、许可或论文。逐项记录真实链接、revision、阅读范围、发现时间和核查状态。明确区分发布方声明、第三方报告和团队实测。
4. 模型保留模态、任务、规模、许可、开放范围、运行支持和限制。架构、运行框架及输入输出可在正文写明，按现有 13 列产出模型 CSV。Benchmark 记录数据规模、指标、协议、用法和端侧相关性。制品记录基座和训练关系、发布身份、格式、精度、文件和测量条件，速度、显存和效果只用本制品的可核验证据。
5. 模型和 Benchmark 分别按对象及 revision 成文。正文含基本信息、适用范围、能力与实现、评测口径、制品及运行、限制与待核实项、来源与阅读范围。事实就近引用 `[S1]` 等编号。量化明细进量化 CSV，相关材料归入对应模型正文。对已有正文保留人工内容并记录拟议差异。

## 飞书交付

日报根目录沿用现有 `model/benchmark日报`。本工作流程文档另放在用户指定的工作资料目录。

| 产物 | 相对日报根目录的路径 | 内容与格式 |
|---|---|---|
| 模型日报 | `model/model_daily_{date}.csv` | 13 个现有字段 |
| Benchmark 日报 | `benchmark/benchmark_daily_{date}.csv` | 14 个现有字段 |
| 渠道清单 | `channel/channels_{date}.csv` | 12 个现有字段，渠道 ID 延续原清单 |
| 来源清单 | `channel/source_links_{date}.csv` | 7 个现有字段，用于追踪来源和核查状态 |
| 量化与衍生制品日报 | `quant/Quant Trail_daily_{date}.csv` | 29 个现有字段，以制品文件与修订为粒度 |
| 调研正文 | `md/{date}/` | 原生 Markdown，沿用 `models_组织__仓库_短revision.md` 和 `benchmarks_组织__仓库_短revision.md` |

CSV 使用 UTF-8 BOM、原列顺序和标准逗号分隔格式。多行及逗号由 CSV 引号封装。数值列只填明确的单个值，未知填空，额外测试参数进说明列。零新增时可以发布仅含表头的 CSV，上传回读后按文件名及 SHA-256 写本地交接文件。没有模型或 Benchmark 正文时无需创建空的 Markdown 日期目录。

## 校验、发布与下游任务

1. 将文件先生成到私有暂存目录，记录业务日期、扫描范围、候选对象、来源、未覆盖项、产物计数和 SHA-256。检查 CSV 表头和列数、可写类型、关键身份、重复记录和实体对应关系。分别验收 CSV 与正文覆盖范围。
2. 发布时按目录和文件名核对飞书现状。已存在且内容相同视为成功。已有不同内容需要对账，提交结果不明先回读。逐件核对远端位置、唯一文件名、内容散列和行数。
3. 正式业务日期只接收有本地 Codex 交接回执、文件名和 SHA-256 匹配的 CSV，各表独立同步，校验服务独立只读检查。模型表完成后，评分服务核查文字输出语言模型的代码、Agent、数学成绩，沿用冻结版本和证据规则。服务器更新 `md/README.md` 的资料索引和统计。`md/existing/`、`md/backfill/` 作为历史资料保留。
4. 同一日已存在内容不同的 CSV，或当天 Markdown 目录已有其他生产者的文件时，中止发布并保留状态供对账。生产入口不控制外部 Grokbot 定时任务。

## 运行入口

生产入口为 `daily_producer.py`，由 `model-research-producer.timer` 触发。目录结构与飞书日报一致。`coverage.json` 记录业务日期、时间窗、扫描入口、未读来源、候选范围和文件行数。备查原始材料、模型决策、发布回执和交接文件留在服务端私有目录。

```bash
python3 skills/model-research/scripts/daily_delivery.py check \
  --config <现有CSV配置> --date <业务日> --bundle <暂存目录>
```

正式运行由 producer 完成查重、飞书上传、回读与下游交接。发生中断后使用同一批文件与发布回执接续。校验结果写入暂存目录的 `delivery-check.json`。部署后以首次自然触发的上传回读及实际同步结果验收。
