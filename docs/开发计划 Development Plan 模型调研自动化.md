## 当前目标

当前目标是将Grokbot已经准备的模型日报、Benchmark日报及渠道快照，经过字段匹配与格式统一后直接增量同步到飞书。用户已明确不需要逐条重新调研，Codex和MD正文不作为日常同步依赖。原件归档、人工保护、评分公式和source_links/backfill排除规则继续保留。

| 阶段 | 工作及依赖 | 产物与验收 |
|---|---|---|

| M1 接收与身份 | 实现分页发现、下载、不可变原件、业务日/版本、实体匹配和 SQLite 状态 | 以本次 489→67→14 的来源演变做回归；同名替换可识别、渠道ID重编不串写 |
| M2 档案与候选 | 实现 Markdown 模板、证据清单、AI 执行器协议与输出校验 | 一批资料能生成有出处的档案；未知信息不编造，正文指令不执行 |
| M3 计划与冲突 | 实现字段三方比较、schema 校验、plan 与只读预览 | 人工变更保护；冲突不覆盖；相同输入的第二次计划没有多余写入 |

M0–M4 是首版实现范围；接收、身份、候选、三方计划、apply/verify/resume 已完成代码和本地验证。已用新程序验证飞书渠道 schema、记录、云盘下载和只读计划。M2 已接入独立Codex，实际读取固定修订模型卡并生成MD正文，含来源、范围、未知项和人工编辑保护。M4已完成真实模型新增、回读、重复计划零操作和既有385条/74列不变核对；M5已启用分批研究及apply调度，有进展时快速接续，长期无人值守继续验收。自动配置已限定可维护字段；既有人工非空值无基线时保留、可补空、新建或按成功基线更新，备注及评分公式不写。

## 首次真实试跑

1. 显式指定业务日及来源文件版本，不把输入 131 个模型和 3 个 Benchmark 理解为应新增这么多条。
2. 对小范围实体读取完整当前值，建立经过核对的初始配对与基线。
3. 生成计划，确认目标字段、证据、变更前值与人工修改保护规则。
4. 在本轮授权内应用并回读；保存结果不明项，独立条目可以继续。
5. 原样重复执行同一批次，验证零重复新增和无意义写入。
6. 注入一项人工变更和一次提交后回执丢失，验证冲突与接续。

## 验证矩阵

| 场景 | 预期行为 |
|---|---|
| 同一文件/业务日重复提交 | 复用已验证产物，不重复创建 |
| 同名文件被替换 | 新版本进入独立批次，原件和历史结果保留 |
| 同渠道ID指向新平台 | 身份冲突，不能继承旧 record_id |
| 人工保护字段变化 | 拉回本地镜像或保留候选，不反向覆盖 |
| 同字段两边改动 | 形成可追溯冲突，不更新成功基线 |
| 缺列、无效选项和缺证据 | 对应字段/记录失败或待核实，不静默吞掉 |
| 空文件和缺文件 | 根据生产方声明区分，无声明不当作完成 |
| 提交超时、返回丢失、回执写失败 | 先回读已知对象，再决定补做；不盲重发 |
| 跨格式 Markdown/Docx 交付 | 使用 document-sync 的独立双侧回执，不比较不同格式原始哈希 |
| 凭据失效、配置丢失、ACL拒绝 | 分类故障，停止受影响平台操作，保留已有成果 |

## 仍需在实际写入或部署前确定的条件

- 各字段的人工/AI/派生归属，以及现有评分规则的正式来源。
- 生产方能否提供完成 manifest；缺失时接受何种就绪判断和迟到窗口。
- 固定运行机、持久存储、Agent 启动方式与模型认证；具体预算和单轮最大工作量。
- Markdown 档案是否需要在线交付；如需要，明确文件夹、配对与方向。
- 定时任务的项目、时区、时间和长期写入范围。当前试运行按用户最新要求在北京时间12:00开始，18:00前有进展时1分钟接续、空闲时30分钟重查，后续长期服务仍需验收。

这些条件不阻塞离线接收、身份与计划模块的开发。它们会阻止对应的真实写入、平台集成或无人值守验收，不能靠默认值冒充确认。

## 后续扩展

接入更多渠道 adapter；来源变化触发复核；在单独范围内接入 source_links、历史回填、派生评分统一重算。开始真实模型比较时，另用 research-plan 定义研究问题、对照和指标，不以工程测试代替能力结论。
