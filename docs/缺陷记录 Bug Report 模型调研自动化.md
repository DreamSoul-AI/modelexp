## CSV直接同步修正

- FLOW-01：将Grokbot成品CSV再次交给模型逐条核查，导致已有内容未写入。按用户明确要求关闭研究执行器，以CSV优先，直接映射和同步。
- SELECT-01：官方field-list的发布者选项仅返回前50项，另138项标记截断。改用field-search-options完整分页；单选名称保留内部标点，多选支持中文逗号，明确别名复用现有标签。新发布者按白名单追加，保留旧选项与字段属性。
- EMPTY-01：原空下拉值是[]，旧bootstrap_empty只接受null，导致已存在记录的空白无法补齐。现在同时识别空数组和空字符串。
- URL-01：单链接列直接写入“仓库标签；URL”后，飞书转换成错误链接。URL列只提交规范链接本体，复合原文保留归档；实际83条结果不明操作经原请求与其他全部字段逐项匹配后，修正URL并回读对账，没有重复新增。
- BATCH-01：逐记录全表读取和提交增加耗时。按表合并最多200条，提交前重读目标、提交后统一回读；丢回执和并发人工修改回归覆盖。

本轮证据见 [CSV直接同步](<运行记录 Run Record/2026-11-14 CSV直接同步.md>)。

## AI误关与任务耦合

- FLOW-02：将“CSV直接同步”误扩展为关闭全部AI研究，原需求中的MD正文停止。现增加独立research入口和mode=research部署，恢复真实模型阅读及正文。
- LOCK-01：同状态目录中的外部模型调用会长时间持有writer锁，影响CSV。独立AI配置采用另一state_dir、数据库、进程和MD目录；双向锁隔离回归与实际并行CSV成功验证。
- QUEUE-02：只看当天输入会使昨日未完成研究失去接续。新工作集合合并同配置的最新正常日报，按完整身份采用最新输入，当天优先，不读取排除的backfill文件。

验证见 [独立调研与MD恢复](<运行记录 Run Record/2026-11-15 独立调研与MD恢复.md>)。
