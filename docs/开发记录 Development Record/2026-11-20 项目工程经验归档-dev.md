# Model 调研工程经验

## 源文件同名不代表同一批内容

本项目渠道CSV曾在同一业务日从489条调整为67条再调整为14条，文件名仍沿用当天日期。有效做法是保留远端token和下载哈希，生成独立来源版本，并固定本轮输入；只比较名称或修改时间不足以证明内容一致。用于上游可能替换、纠错或重传文件的场景。

## 来源编号与实体身份分别管理

上游重新编排渠道ID后，相同ID可对应不同平台入口。跨批应结合规范化URL与主体核对内部实体，保留别名并重建record_id关系；不能直接沿用旧基线。依据见 [渠道重拉记录](<../同步核对 Sync Review 渠道重拉 2026-11-14.md>)。

## CSV导入需要核验类型和单元格

飞书导入器曾把“备注”识别成多选并拆分。只检查489行导入成功会漏掉语义变化。首次导入后检查schema、日期、多选、链接和空值的归一化结果，修正类型时用备份恢复原文并回读。后续增量写入采用显式类型映射。

## 网页确认与本地授权保存分别验证

CLI默认凭据目录只读时，网页确认成功仍可能导致本地保存失败。先区分目录、应用配置、用户授权、scope和资源ACL，使用官方支持的配置/数据目录变量；应用配置和加密材料要一起保留。当前只验证本实例保存与登录，跨任务续期仍待验证，不据此承诺永久免登录。

## CLI成功结果按命令协议解析

Base NDJSON读取返回manifest，未必含`ok`。按退出码、业务信封或manifest类型判断，并核对实际文件和分页，避免将有效空表误报成失败。此做法适用于有导出型快捷命令的适配器，不将单一信封规则套用所有命令。

## 未知提交要阻断后续实体写入

仅在原计划内避免重发仍不足：同一来源的新版本可能生成新操作ID，从而绕过旧提交。首版把 submitting/submitted/unknown 与实体绑定，新计划暂缓该实体，verify/resume 先对账；远端尚未可见时继续保留未知，避免迟到请求造成重复。适用于无请求幂等键、异步落库或回执可能丢失的外部写入，不能据此承诺跨系统事务。验证见 [首版运行记录](<../运行记录 Run Record/2026-11-14 自动化首版实现验证.md>)。

## schema指纹排除非语义顺序

飞书字段列表返回顺序可变；直接哈希完整schema会误判结构变化。首版按field_id排序，选项按名称排序，忽略展示颜色，保留类型、选项、关联和公式等语义。回归覆盖“仅换序可执行”和“实际改名阻断”，适用于字段API存在非稳定展示顺序的同步计划。

## 同仓库同修订也可能有多个模型变体

今日CSV里9B/4B、big/small、T2V/I2V存在共用仓库URL和revision的情况。只有这两个字段会发生身份碰撞；核对原始行后，在组合身份中增加明确的变体名称，同时保留URL与revision。名称不能独立匹配，身份规则改变时保留旧状态，避免继承不对应的record_id。验证与适用范围见 [云环境试运行](<../运行记录 Run Record/2026-11-14 云环境试运行部署.md>)。

## 后台Agent的实际调用要单独验证

本实例codex login status能显示已登录，但独立模型调用实际返回401和刷新失败；当前聊天可用不能证明后台执行器可用。部署预检既要检查文件目录，也要完成一次真实模型调用；未通过时服务明确标记waiting_research并保留请求，不将采集档案记成调研完成。这里只验证当前云实例，不推断其他机器的Codex登录状态。


## 后台状态目录与聊天默认目录分开

本次跨环境后，默认Codex目录的登录再次失效。后台改用专用仓外私有目录，以CLI官方状态设置仅作用于子进程，重新完成浏览器授权，并用真实模型调用确认。默认目录的login status与实际可调用性分别检查；私有目录/授权文件使用700/600权限，不随源码或共享环境发布。目录保存成功尚不能证明下次云环境或过期续期成功，恢复时仍需实际核验。

## 完成来源整理与核实所有信息分别标记

仅阅读模型卡时，权重、精确参数、量化制品、许可证全文与社区反馈往往仍未知。researched应表示本轮指定来源已整理，并明确列出未知项，不能把未知全改为已验证，也不能因仍有未知而永远不推进队列。身份或版本不符时保留needs_review。实际示例及回执复用见 [正文接入记录](<../运行记录 Run Record/2026-11-14 后台调研与正文接入.md>)。


## 自动维护要落实到实际apply而非长期只读

用户目标是自动同步时，研究和计划完成不能替代线上写回。应在已授权目标与字段范围内落实输入就绪、身份保护、初始化规则和回读；不因默认开关未配置或上游没有新增manifest就长期停住。当前用稳定观察、既有人工值保护、新增/补空和程序基线维护跑通真实写入，原385条/74列保持不变。

## 独立条目不要被无关问题长期阻断

不完整历史行仅对相关名称/来源阻止重复创建；研究失败保留原输出和已验证候选，其他合法变更继续。发现模型重复章节时可保留全文及证据合并格式，而不编造结论或再调用模型。实际恢复、重放零操作及107项回归见 [自动写回记录](<../运行记录 Run Record/2026-11-14 多维表格自动写回.md>)。

## 成品CSV同步不应默认再跑研究

用户明确提供可直接采用的Grokbot成品CSV时，应把列映射、下拉标签统一、链接格式和重复检查作为日常同步步骤；额外模型研究独立按需进行，不能阻塞已有信息的搬运。现场发布者field-list实际只返回50/188项，必须补全分页，不能从截断响应断言选项不存在。单选名称内部逗号不拆分，多选才拆；URL列只写链接本体，原复合单元格归档。整份输入首次提交后统一回读，并重复规划验证零冗余；局部写入成功不是字段完整性验收。具体见 [CSV直接同步运行记录](<../运行记录 Run Record/2026-11-14 CSV直接同步.md>)。

## 运行档案与公开阅读快照分开

程序MD前置信息含状态和候选证据，不适合直接作为公开报告；旧模板占位章节还会与自动正文重复。采用保留私有结构化元信息、精确清理系统占位区，并只导出生成段的方式，可以保留恢复能力和人工笔记，同时交付清晰报告。导出前验证生成指纹，导出后用清单哈希保护人工修改；迁移状态包独立于Git和认证。实际交付见 [定稿记录](<../运行记录 Run Record/2026-11-15 Markdown定稿与服务器交付.md>)。
